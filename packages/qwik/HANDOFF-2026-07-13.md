## 3. Decisions & learnings NOT (fully) recorded elsewhere

- **Commit conventions**: one component per commit, `feat(qwik): add <Name>`;
  author/committer forced via `GIT_AUTHOR_NAME=Claude
  GIT_AUTHOR_EMAIL=noreply@anthropic.com GIT_COMMITTER_*=...` env vars —
  plain `git config` is silently overridden by session-level `GIT_*` env.
- **Ephemeral files the documented workflow leans on** (regenerate if gone):
  - `/tmp/zag-overrides.json` — map of `@zag-js/*` → `../zag/...` paths;
    regenerate by walking `/home/user/zag/packages/**/package.json` names →
    relative dirs (see PLAN Part 1 / `scripts/src/symlink.ts` for the
    canonical shape, or use `bun run local:sync`).
  - `/tmp/bun.lock.bak` — just the committed lockfile: restore with
    `git show HEAD:bun.lock > bun.lock`.
- **`fixedCropArea` "bug"** (final batch note): a defect in OUR port draft —
  the key was initially missing from image-cropper's `machinePropKeys`, so
  the prop would have leaked to the DOM instead of reaching the machine; the
  SSR gate caught it pre-commit. NOT an upstream zag bug. Lesson reinforced:
  machinePropKeys lists are transcription-error-prone — diff them against the
  solid `createSplitProps` list during review.
- **Parity gaps & closability** (all have in-code comments):
  - `MarqueeEdge` without `<Slot/>`: trivially closable (add the Slot);
    queued below.
  - `JsonTreeView.renderValue`: closable by design — offer `renderValue$`
    (QRL) per the R9 convention, invoked per leaf; needs a per-node QRL-call
    render helper. Medium effort.
  - `Frame` children into iframe document: HARD — Qwik has no cross-document
    portal and event delegation is registered on the top-level document only;
    a moved subtree loses interactivity. Revisit only with an upstream Qwik
    mechanism.
  - `Toaster` `renderToast` prop instead of function-children: forced by
    `component$` typing (children-as-function collapses to `never`); keep.
- **PLAN gaps to backfill** (found in the last batch, not yet folded into
  PLAN because it was frozen mid-batch): `downloadFile` from
  `@zag-js/file-utils` triggers anchors via `dispatchEvent`, so tests must
  spy on `dispatchEvent` not `.click`; the qwik `environment.getWindow()` is
  typed `Window` (not `Window & typeof globalThis` like solid/react) —
  consider widening the provider type instead of local casts.
- **Branch/PR strategy (recommendation, not yet ratified)**: keep
  `claude/busy-noether-lu8dvd` as the "core qwik support" PR. Build website
  wiring + changeset on a separate branch stacked on it, PRed separately
  after core lands — website changes touch shared infrastructure and review
  cleaner alone. The changeset (a `.changeset/*.md` file declaring the new
  `@ark-ui/qwik` package + semver intent) is one small file; it can join
  either PR, but the RELEASE itself is hard-gated on `@zag-js/qwik` being
  published to npm (it's an unpublished fork at 1.31.1 — see PLAN Part 1).
- **Multi-agent process hazards** (cost real time; avoid repeating):
  subagents doing long batches sometimes die silently mid-component — detect
  via "no new commits AND no build/test processes", revive by re-messaging
  the SAME agent (it resumes with context); never run two agents in one
  working tree (a resumed agent + its replacement collided once); shell
  watchdogs must avoid self-matching `pkill` patterns and `grep -c` exit-code
  traps; PLAN.md suffered a file-watcher duplication bug when edited
  incrementally — always rebuild it from `git show HEAD:...` into /tmp and
  `cp` + `git add` atomically.

## 5. Trying it manually / consuming from another project

Today (build not wired), the package is consumable as **source**:

1. Bootstrap per PLAN Part 1 (sibling zag clone on the adapter branch,
   `local:sync`, `bun install --ignore-scripts`, node_modules relinks as
   listed there).
2. Quickest hands-on: add a story-like route — create a scratch Qwik app
   (`npm create qwik@latest`, pin `@qwik.dev/core` to the beta in
   `packages/qwik/package.json`), then in its vite config alias
   `@ark-ui/qwik` → `<ark>/packages/qwik/src/index.ts` and each `@zag-js/*` →
   the zag checkout's package `src/` dirs (mirror the override map). Qwik's
   optimizer in the app will compile the TS sources directly — this is
   exactly how the browser test harness consumes it.
3. Or stay inside the repo: the fastest interactive loop is writing a
   scratch `*.browser.test.tsx` (fixtures in `tests/basic.tsx` per R16) and
   running `vitest run --config vitest.browser.config.ts <file>` — real
   Chromium, real SSR available via `renderSSR` once the fork fix is
   consumed.
4. After I2 lands, `bun run qwik build` + `npm pack` in `packages/qwik`
   gives a tarball installable in any Qwik app (still requires `@zag-js/*`
   including the unpublished `@zag-js/qwik` to resolve — full external
   consumption is gated on publishing the adapter).
